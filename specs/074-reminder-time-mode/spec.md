# 提醒侧时间模式三档（FL Issue #373）

## 背景

嘀嗒《01-任务/07-固定时间与固定时区》把提醒的时间语义分成三档：浮动、固定时区、固定时间。
任务侧的同一套档位已存在于 `origin/develop`（FL Issue #369 / PR !372），提醒侧此前只有一个
`fixedTimezone` 布尔位，出站同步 payload 也不带档位，因此矩阵第 12 行「时间模式」在提醒这一面
只能停在「部分」。

## 判据源原文（照抄，不改写）

- 固定时区：`任务的时间会随着所在时区的不同而改变`
- 固定时间：`不论所处时区如何变化，任务的时间都会保持一致`

取自 zh-cloud-docs 镜像 `todo/99_参考资料/dida365-help-center/02-功能指南/01-任务/07-固定时间与固定时区.md`，
与任务侧 specs/055 用的是同一页、同一口径。

## 功能需求

- FR-1 提醒表要有自己的档位字段，取值与服务端 `todo_reminder.time_mode` 一致：
  `0` 浮动 / `1` 固定时区 / `2` 固定时间（服务端契约见 zh-cloud-service Issue #292）。
- FR-2 只有旧布尔位的存量提醒必须被解释成「固定时间」，不得读成浮动：
  `fixed_timezone = 1 → time_mode = 2`，与任务侧 specs/055 和服务端 !291 的口径同一条。
- FR-3 提醒编辑器要能选中三档中的任意一档，选中结果必须落进本地库、并带上同步出站 payload。
- FR-4 「设置 → 日期与时间 → 时区」总开关关掉时，「固定时区」这一档不出现；
  这条显隐已由 `test/features/task/reminder_timezone_gate_test.dart` 判，本轮只把它的 key 跟上新控件。
- FR-5 保存失败必须给出可见原因，且库里不得留下半写的档位。

## 范围外

- 服务端触发时刻按档位换算的算法面（zh-cloud-service Issue #302 A 面）不在本规格内。
- 提醒的服务端往返（同步下行）不在本规格内：本轮只保证出站带上档位，落库仍走本地 Drift。
