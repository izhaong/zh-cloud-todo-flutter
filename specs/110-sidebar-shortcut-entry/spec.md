# 规格：侧栏「快捷键」入口（FL #581，矩阵 #86 的第三种进法）

## 判据源（嘀嗒原文，zh-cloud-docs 镜像）

`todo/99_参考资料/dida365-help-center/03-特色功能/08-桌面快捷键.md` 常见问题那段：
- `:26`「在设置里查看快捷键界面，可以修改。」——specs/109 面③ 已落地。
- `:27`「在侧边栏打开快捷键界面，可以修改。」——**本规格**。
- `:28`「在「指令菜单」-「帮助」-「显示键盘快捷键」打开快捷键界面，可以修改。」——
  specs/109 面① 已落地（本端把两级结构展平成一级）。

## 需求与裁定

1. **落点是侧栏底部 dock 的第四枚按钮**（`lib/features/shell/sidebar.dart` 的
   `_EfficiencyDock`，与番茄专注/习惯打卡/倒数纪念日并列），标签「快捷键」、
   tooltip「键盘快捷键」。嘀嗒那页讲的是桌面端，本端 dock 只在 wide/compact 两个桌面形态画 ⇒ 对得上。
2. **不新增第二个界面**：点它走 `showKeyboardShortcutsDialog`，
   并带上与设置页同一份 `shortcutOverridesProvider` 生效值与 `sidebarVisibilityRepositoryProvider`
   落库通道 ⇒ 三处入口说同一套话。`Sidebar` 本身就是 `ConsumerWidget`，
   所以这条回调在侧栏内部闭环，不需要 `HomeShell` 再透传一层（少一根线就少一处会写散的地方）。
3. **它不是"功能模块"**：`TodoFeatureModule` 那三档（四象限/番茄专注/搜索）不许顺手把它一起收掉，
   用例钉着"关掉番茄之后快捷键那枚还在"。
4. **可见按钮而不是暗门**：本可以塞进长按/右键菜单做到零像素改动，
   但那样这条主张就变成"藏起来的等价物"（人的既有反馈：功能别都挂菜单）⇒ 选可见按钮，
   代价是重录黄金基线（见下）。

## 黄金基线：动了哪 5 张、为什么可以收

`flutter test --update-goldens test/visual/todo_workspace_golden_test.dart` 后
只有 `wide-populated`、`wide-selected`、`wide-empty`、`wide-long-content`、`compact-selected`
这 5 张变了（tablet/mobile 那 4 张一像素没动 ⇒ 只有画着侧栏的形态受影响）。逐张现量的差异范围：

| 基线 | 差异像素 | bbox（x0,y0,x1,y1） |
| --- | --- | --- |
| wide-populated | 21896 | 29,852,1439,883 |
| wide-selected | 28581 | 29,852,1439,883 |
| wide-empty | 28380 | 29,852,1439,883 |
| wide-long-content | 21896 | 29,852,1439,883 |
| compact-selected | 17541 | 85,752,1279,787 |

三条排除性证据（都是现量出来的，不是推测）：

1. **几何没动**：带改动与不带改动各跑一次探针，`ReorderableListView` 两张的矩形
   完全一致（侧栏清单 `57,536,329,696`、任务列表 `330,100,1007,900`），
   只有 dock 按钮自己的 x 变了（习惯那枚 `150.3..235.7` → `129..193`，一行从三列变四列）
   ⇒ 没有元素被挤动。
2. **没有溢出/异常**：golden 跑完没有 `RenderFlex overflowed`，结构断言与
   `expect(find.textContaining('加载失败'), findsNothing)` 都过。
3. **判据不是噪声**：不带任何代码改动重跑 `--update-goldens` ⇒ 9 张全部零差异
   ⇒ 这套 harness 是确定性的，上面那 5 张的变化确实由这次改动引起。

差异集中在窗口底部那条带（wide 的 y 852-883、compact 的 y 752-787，都是 dock 那 46px 的高度带），
数值上是灰度 Δ≤3/255 的抗锯齿差（如 `25,25,25` → `28,28,28`）加上新按钮自己的墨迹。
**登记为已知残留**：几何与结构都证过没动，但"为什么内容区那几行文字的抗锯齿也变了"
本轮没有查到根因（最像是绘制批次变化带来的 AA 差异）。收进基线而不是压掉，
是因为它可复现、可回退（git 里换回旧图就行），且下一轮若再动 dock 会立刻在同一处显形。

## 测试与探针

- `test/features/shell/sidebar_shortcut_entry_test.dart` 3 例：
  ① 点侧栏那枚 ⇒ 打开同一个界面、不是只读、两枚「修改」都在、在这里改的键落库；
  ② 存过覆盖之后从侧栏进去显示的是生效键位（`Ctrl+Alt+J`）而不是注册表默认；
  ③ 关掉番茄专注后 dock 少一枚、「快捷键」那枚不许跟着消失（正对照在前）。
- 变异探针 ㉝–㊱：㉝摘掉第四枚按钮 ⇒ 三条全红；㉞落库通道传 null ⇒ ①红在只读那格；
  ㉟生效键位传空表 ⇒ ②红。各自红在期望用例上、还原后与提交字节一致。
