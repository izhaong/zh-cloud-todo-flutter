# 066 日历任务拖入清单详情区域（嘀嗒矩阵 #32 拖动排期 ②）

## 背景

嘀嗒《02-功能指南/02-日历/07-任务与日历同时显示.md》在「拖动排期，让安排更高效」一节列了四面，
本规格只做 ② 面：

- `:53`「将日历中的任务拖入清单详情区域：」
- `:55`「任务会从原所属清单迁移到当前查看的清单中，并保留其原有的时间安排。」

同族另三面各归各单：①「将清单中的任务拖入日历」已由 specs/065 落地（FL `1723e725ac`）；
③「拖动到清单或标签上」＝ FL Issue #399；④「拖动到智能清单上」＝ FL Issue #400。

## 结论（术语照抄源页）

1. **落点**是「清单详情区域」= 并列视图里那块清单任务列表区，不是侧栏、不是清单行的拖放排序位。
2. **效果只有一个**：换「所属清单」。时间安排：截止日 / 起止 / 全天标记，一个字都不动 —— 源句「保留其原有的时间安排」。
3. **分组（Section）跟着清单一块清掉**：分组属于原清单，留着她会把旧清单的 `sectionId` 带进新清单。
   源页没写这一条，是实现约束，写在下面「范围与不做」。
4. **同清单不落**：任务已在当前查看的清单里时，这不是一次迁移，落点不接受、不画高亮、不发写库。

## 范围与不做

- 只在「选中了具体清单 + 视图模式＝列表」时挂落点。看板与时间线各自已有 `DragTarget<TodoTask>`
  （`lib/features/task/views/kanban_view.dart`、`views/timeline_view.dart`），
  外层再套一个落点会跟它们抢同一批拖放，所以本规格不碰那两个视图。
- 不做 ③④ 面，不做「多选批量换清单」（那是 FL Issue 里另一族）。
- 不改后端契约：换清单是既有 `TaskRepository.update(listId: …)` 的能力，
  同步侧走既有 outbox upsert，无新增列、无新增端点。
