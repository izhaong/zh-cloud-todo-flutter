## 之前的仓内状态

清单页的数据源只给顶层任务（`lib/state/repositories/task_repository.dart` 的
`watchTopLevelByList`，智能清单那支是 `watchAll`，两条都带 `parentTaskId IS NULL`）⇒
子任务不作为行。于是 FL #590/#595 把一行拖成子任务之后，**那一行直接从列表里消失**，
`:31` 那句在清单页也看不见。

## 需求与裁定

1. **子行紧贴其父，而不是按自己的 dueAt 去别的组。**
   `entries` 的构造从"分组头 + 组内顶层行"改成"分组头 + 每行后面紧跟它展开出来的子树"
   （`_subtreeOf`；复算 `git grep -c "_subtreeOf" -- lib/features/task/tasks_by_list_page.dart` ⇒ 4）。
   父行不在可见序列里时子行绝不自己冒出来（用例「子行只挂在渲染出来的父行下面」用最直接的
   一种情形断这条结构：挂一个"父不在本视图"的子级，它不该出现在任何位置）。
2. **默认收起。** 裁定理由：原文那一节的标题就是「展开子任务」、写的都是"点击箭头来展开或者收起"
   ——默认呈现就是收起态。给的推荐与交叉验证一致（cursor-agent，输出 1009 字节、结尾 `CROSSCHECK: DONE`）。展开集合是**本地 UI 态**：不落库、不进同步队列（原文没说要跨设备记住）。
3. **箭头位置分两端**（`:78` 右侧、`:86` 左侧），不是同一个位置：
   同一颗 `expander` 由 `desktopMode` 决定挂在行 Row 的头还是尾，
   desktop 那一头**不等 hover 才出现**（收起态没有入口就谈不上"可以展开"）。
   复算：`git grep -c "subtaskExpander" -- lib` 两个文件各命中（页面构造 + 行宿主透传）。
4. **层级要看得出**：子行按 `depth` 缩进（一行内最前面那块跟着缩，行表面本身铺满整宽，
   所以判据量的是勾选框的左边界而不是行矩形）。三层树那条用例逐级比左边界。
5. **展开不是写操作 ⇒ 只读清单也该能看树。**
   `writable=false` 关的是写操作的落点，箭头不受它管（用例在自建清单上种一对父子再置只读，
   断箭头在、点开不弹 SnackBar、库里父子关系没动）。
   ⚠️ 这条判据**不能拿收集箱量**：`_subtaskDropEnabled` 对收集箱是"页身份先判真"，
   把箭头挂到 writable 上的变异在收集箱里根本不会红 —— 探针 T9 第一版就是这么假绿的，
   换到 `workList` 才咬住（见 `tasks.md` 的自纠记录）。
6. **放置排序那两块加一道"只接同一父级的兄弟"**（`_acceptsPlacement`；
   复算 `git grep -c "placementZone" -- lib/features/task/task_subtask_drop.dart` ⇒ 4）。
   交叉验证点名的正是这件事：渲染按父归堆，跨父的插入位在那棵树里没有对应位置，
   收下这一刀只会写出一个"归堆后被弹回原处"的顺序 —— 就是"看着能落、落下去没反应"。
   换父本来也不是放置的活：`:20`/`:49` 给的是右下那块。
   行首手柄那条**不加**这道条件：`ReorderableListView` 的扁平下标经归堆后等价于
   "落到本组最近的缝"，看得见移动（用例「拖到已展开的父的左下」断的就是归堆后子树仍连续）。
7. **子级另走一条流，顶层那条一字不改**（`watchSubtasksByList` 与 `watchAllSubtasks`；
   复算 `git grep -cE "watchSubtasksByList|watchAllSubtasks" -- lib` ⇒ providers 与仓储各 2）。
   筛选、计数、看板/时间线那些面的既有口径都是"顶层任务 = 列表项"，
   把子级混进同一条流会顺带改掉它们的语义。
