## 需求与裁定

1. **分组是渲染层的事，命令表仍由调用方给出，面板不改写顺序之外的内容。**
   `TodoPaletteCommand` 加一个可选 `group`（`lib/features/home/command_palette.dart`），
   面板按"未分组在前、分组按首次出现顺序、组内保持调用方给的顺序"排；
   复算：`git grep -c "group" -- lib/features/home/command_palette.dart` ⇒ 12（模型字段、
   分组渲染与助手方法在这个文件里都提到它）。
2. **组标题只在组内至少有一条命中时出现。** 输入把整组筛空还顶一个标题，
   就是"看着有这层、点进去什么都没有"——那条用例（「输入把整组筛空时，组标题跟着消失」）
   带清空后标题回来的正对照，免得它绿在"标题根本没渲染"上。
3. **只有「显示键盘快捷键」归进「帮助」。** 交叉验证明确点了这一条：
   `:28` 只把这一项放在「帮助」下，把「全局搜索」也归进去是原文没有的项 ⇒ 全局搜索保持不分组。
4. **回车不许把标题当命令。** 标题是 `Padding`+`Text`，不是 `ListTile`，
   `_runFirstMatch` 走的还是命令列表；用例「只有分组命令命中时，回车执行的是命令本身」钉这条。
5. **`:28` 的后半句"可以修改"要端到端量。** 光断"有修改按钮"不够：
   新增用例从真实 ⌘K → 帮助 → 显示键盘快捷键 进去，按下 `Ctrl+Alt+J`，
   再从 `shortcutOverridesProvider` 读回 `showShortcuts -> ctrl+alt+0x6a` ⇒ 改的这把键真的落库。
   复算：`git grep -c "testWidgets(" -- test/features/home/command_palette_test.dart` ⇒ 12
   （本轮之前是 8，新增 4 条）。

## 两处按"限制说明"处理、不占功能面（并给证伪命令）

- `:13`「Mac 应用程序暂时不支持此功能」是嘀嗒自己 Mac 客户端的限制。本端桌面与 Web
  都能用 ⌘K ⇒ 记**超出原文**，不算缺口，也不因为"嘀嗒没有"而砍掉本端能力。
- `:29`「显示为灰色的快捷键不能修改」是一条限制，不是功能。本端注册表里两档
  （打开指令菜单、显示键盘快捷键）**都可改**，所以没有"单行灰色"这个实例；
  本端**没有**这句的对应实现，也不假装对应：整个对话框的只读态
  （`keyboard-shortcuts-readonly`）说的是"落库通道未就绪"，`validateShortcutOverride`
  说的是"提交时拒绝坏组合"，两者都不是"某一行灰掉且点不动"（交叉验证点破了这点，采纳）。
  证伪命令（量"没有灰色不可改的行"这件事本身）：
  `git grep -c "Key('keyboard-shortcuts-edit-" -- lib/features/home/keyboard_shortcuts_dialog.dart` ⇒ 1
  （改键控件只有一处生成，是否可改由 `_editable` 一个开关决定，不存在"某一行被单独涂灰"的代码路径）。
