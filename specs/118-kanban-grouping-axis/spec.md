# 118 · 看板视图按「智能分组」轴开列（矩阵 #15 面 ⑦，FL 无单号）

## 背景

嘀嗒《02-功能指南/01-任务/08-不同的视图查看任务/02-看板视图：分类管理任务.md》：

- `:55`「也可以排序中选择**时间+优先级**」
- `:59`「还可以在「今天」排序中选择清单+时间」
- `:78`「在排序中选择**指派人+时间**」
- 常见问题 `:205`「智能清单支持看板视图…选择不同的分组方式」

本端看板此前只有两态：priority 固定四列 / 清单分组（sections）列；
workspace 的「智能分组」菜单（specs/100，`SmartGrouping` 六轴）在看板模式下
选了不生效——矩阵 #15 面 ⑦ 的缺口。

「时间+优先级」等的语义＝列按第一轴分、组内按第二轴排。列表视图的
`groupTasksSmartly` 已经产出六个轴的桶、组内顺序就是当前排序
（`_visibleTasksInListOrder` 的输出序），看板直接消费同一份输出即可，
不另起枚举（cursor-agent 交叉验证推荐方案 A）。

## 目标（FR）

- FR-1 看板模式（清单无分组、或智能清单）下，「智能分组」菜单选中任意轴
  ⇒ 看板列 = 该轴的桶（`groupTasksSmartly` 输出，空桶不出现）。
- FR-2 拖拽写回：
  - `byTime`：拖进 `今天/明天/最近 7 天/以后` ⇒ dueAt 落到该桶代表日
    （保留原时刻；「无日期」列 ⇒ 清 dueAt）；「已过期」列不可拖入（给可见提示）。
  - `byPriority`：写 priority（高3/中2/低1/无0）。
  - `byList`：写 listId（同名清单取第一个，与分桶口径一致）。
  - `byAssignee` / `byTag` / `byCreatedAt`：不可拖（抛 StateError 转可见
    SnackBar），不静默吞拖拽。
- FR-3 清单里建了分组（sections 非空）时保持分组模式（行为不回归）；
  `none` 仍是 priority 四列。轴列模式下列重排/折叠/列内排序/列头「+」
  都不给（嘀嗒该形态下没有这些要求），分组管理入口不丢。
- FR-4 全部写失败（只读清单、断网）走既有 `_moveTask` 的 SnackBar + 重试。

## 验收（AC）

- AC-1 清单看板选「按时间分组」⇒ 列出 已过期/今天/…/无日期 桶列；
  任务拖进「明天」列 ⇒ dueAt = 明天（保留原时刻）。
- AC-2 「按优先级分组」⇒ 拖进「高优先级」⇒ priority=3。
- AC-3 「按清单分组」⇒ 拖进某清单列 ⇒ 任务换清单。
- AC-4 「按指派人分组」拖拽 ⇒ 可见失败提示、任务不动。
- AC-5 智能清单（listId==null）看板选轴 ⇒ 列照出、拖拽按轴写回（面 ⑩ 顺带收窄）。
- AC-6 门禁：analyze 0 issue、新用例全绿 + 探针、全量不回归。
