## 改动

1. `TodoTaskMergeApi`（POST /task/merge）+ `TodoTaskMergeResult`（warnings 不静默）；
2. 批量动作 `TaskBatchAction.merge`（「合并到…」）进 more 菜单（linkToParent 旁）；
3. `_selectBatchMergeTarget`（同清单候选 + **后果前置可见**）+ `_applyBatchMerge`
   （**未同步任务拒绝并说明** —— 照单条指派既有纪律）；
4. 成功/失败文案：warnings 逐条告知；失败走 `describeError`。

## 判据（2 条）与探针

| 判据 | 咬什么 |
| --- | --- |
| more 菜单有「合并到…」；选中后出目标选择器且**后果说在前面**（"将删除…提醒与重复规则不保留"） | 破坏性动作的知情 |
| **未同步源任务（serverId null）⇒「所选任务尚未同步」拒绝并说明** | 不静默跳过 |

**反向探针**：源未同步静默跳过（continue）⇒ **判据红**。
（⚠️ 第一发探针假绿：源与目标都有"尚未同步"文案、探针跳过源后**目标那条仍触发** ⇒
判据收紧为断言**源**那条原文 —— **断言的文案必须是探针目标路径独有的**。）

## 过程教训

1. **raw-error 门禁第四次抓到我**（合并失败文案插 `error.message` ⇒ 改 `describeError`）
   —— 这把尺子每刀必咬一次，写文案时**先**想 describeError；
2. **探针要打在判据断言的那条路径上**：两条 SnackBar 都含"尚未同步"时，
   断言含糊（`textContaining('尚未同步')`）会让探针假绿 —— 收紧为**源路径独有的原文**；
3. Dart 3.12 null-aware map entry 是 `'key': ?value`（**value 侧**）——
   `?key` 是"key 为 null 才跳"，语义反了。
