## 用户故事
作为记录正数日的人，我在倒数日卡片上点那个数字，就能从「已经 2000 天」换到「5 年」「285 周」再换回来，
因为 2000 天这个数字本身看不出有多长。

## 功能需求
- **FR-001** 倒数日列表每一行的天数文案可点击，点击后在天 → 年 → 周 → 天 之间循环。
  源页 `:97` 只规定「在**天、年、周**三种单位间快速切换」这一**单位集合**，没有规定顺序，也没有说要点几次回到原档 ⇒ 循环顺序（按 `:97` 列举次序排）与「第四次回到天」是**本端实现选择**，不是嘀嗒的要求。
- **FR-002** 单位换算：年 = 天数整除 365，周 = 天数整除 7；只给整数档，不凑「几年几个月」这种源页没写的写法。
- **FR-003** 前缀不变：正数日仍是「已 N 天 / 已 N 年 / 已 N 周」，倒计时仍是「还有 …」。源页 `:93` 的例句「已经恋爱 2000 天」正是正数日。
- **FR-004** 按行独立：一行切到「年」不影响其它行。
- **FR-005** 读屏能单独够到这个天数块：当前单位文案作为 label 可被 `bySemanticsLabel` 命中，且该块的 semantics 节点带 `isButton` 标志。
  实测：`InkWell` 单独**不会**置 `isButton`（摘掉外层 `Semantics(button: true)` 后该断言即红），所以这层包装是必要的，不是装饰。
- **FR-006** 320px 宽 + 1.3 倍字号下三档都能渲染且不溢出。

## 取舍与被否方案
- **落点选列表卡片（`:106` 桌面那一档）而不是详情页（`:97` 移动那一档）**：本端 `lib/features/countdown/` 只有
  `countdown_page.dart` 一个文件、117 行，没有任何详情页；先补详情页等于自创信息架构（嘀嗒的详情页还带样式/备注，
  那些面本 spec 不负责）。因此移动端 `:97` 那一档**仍未满足**，记在「仍缺」。
- **否掉「长按弹菜单选单位」**：源页只说「点击…切换」，没有任何弹层，加了就是发明交互。
- **否掉「把单位选择持久化（SharedPreferences / 契约列）」**：源页没说要记住，契约也没这一列；会话内状态是
  最小实现，持久化属另一面。
- **否掉「年显示为 5 年 5 个月」**：源页 `:93` 问的是「这是多少年，或是多少周」，整数档即可；带余数要自创格式。
- 优先「不改侧栏/dock、不新增 push 路由」的落点（objective 决策规则），本面正好满足：只改一行的 subtitle。

## 四件套自查
| 要求 | 结论 |
| --- | --- |
| 320px + 1.3 倍不溢出 | FR-006 有用例，且档位作用在 `CountdownPage` 自己的 context 上（`Builder` 包在 `home:` 之下、页面之上），不是只包 `home:` |
| 独立可读屏语义 | FR-005：天数块自己的 semantics 节点，`isButton` + label 为当前文案；句柄 `try/finally` 释放 |
| 失败保留已加载数据 | 本面无异步动作（纯本地 setState），不适用；不谎称已证 |
| 过期响应不覆盖新响应 | 同上，本面无网络请求，不适用 |

## 不做
- 不做样式选择器、不做颜色、不做图片上传、不做备注（都要么缺契约、要么会改可见布局需先申请重录黄金基线）。
- 不做「年/周」的小数与余数展示。
