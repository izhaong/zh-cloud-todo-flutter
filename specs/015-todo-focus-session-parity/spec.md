# Todo 专注会话对齐

**状态**：本地完成（外部门禁待补）
**创建日期**：2026-08-02
**后端依赖**：`zh-cloud-service/specs/010-todo-focus-session-parity/spec.md`

## 背景

滴答清单公开帮助把番茄计时、正计时、自定义时长、任务关联、专注笔记和多端会话同步列为专注起步能力。原 Flutter 页面把模式硬编码为三项，只在首次打开时读取活跃会话，无法消费 service 已有 `/pomodoro/presets` 与 CUSTOM 合同；完成备注虽已发送，后端也会静默丢失。本切片已对齐这些合同，正在完成全量门禁与交叉审查。

## 用户场景

1. 用户进入专注页后看到服务端返回的模式名称和时长，可选择自定义 1–1440 分钟并开始。
2. 用户可把本次专注关联到当前账号已同步的未完成任务；从任务详情进入时沿用传入的服务端任务 ID。
3. 专注期间可记录最多 512 字符的笔记，完成时随同一会话提交；失败保留会话和文字，允许重试。
4. 另一端暂停、恢复、完成或取消同一会话后，本端在 15 秒内收敛到服务端状态，不需要重启页面。

## 需求

- **FR-001**：`PomodoroApi.presets()` 必须解析 `mode/focusMinutes/breakMinutes/label`，页面不得继续以硬编码模式作为成功事实源。
- **FR-002**：CUSTOM 模式必须要求 1–1440 的整数分钟；其它模式使用服务端 `focusMinutes`，服务端未给时长的 FREE 模式允许用户指定正计时起始显示值但不伪造休息时长。
- **FR-003**：页面只允许选择 `serverId != null` 且未完成的本地任务，并把服务端 ID 发送给 start；无可选任务时仍允许纯专注。
- **FR-004**：完成备注裁剪后最多 512 字符；请求失败时不得清空当前会话、计时器或备注，页面显示可恢复错误。
- **FR-005**：页面每 15 秒只读刷新活跃会话；同 ID 的 RUNNING/PAUSED 更新状态，不同 ID 替换本地会话，服务端无活跃会话时清理本地状态。刷新失败保留现状并显示非阻断提示。
- **FR-006**：Timer、异步请求和页面销毁必须避免重复轮询、过期响应覆盖与 `setState after dispose`。
- **FR-007**：现有暂停、恢复、完成、取消、统计和任务详情/提醒入口不得回退。
