## 源页与逐面判定
源：`zh-cloud-docs/todo/99_参考资料/dida365-help-center/02-功能指南/05-习惯打卡/02-更好地完成习惯.md`（docs `origin/develop`）。
矩阵行 #45 已按十面逐判（docs PR !97），本 spec 只做其中两面：

| 面 | 源页行 | 原文要点 | develop 现状 |
| --- | --- | --- | --- |
| 回顾：月度打卡表 | `:72`-`:88` | `:77`「点击习惯进入打卡页面，向上滑动即可查看当月打卡情况」；`:84`「点击习惯后，可在右侧查看当月打卡情况」；`:72` 原文「在习惯统计中，我们提供了「打卡概览」和「月度打卡表」」（引号内为原文，未改写） | 列表页顶部只有一张 `AppCard`（`habit_page.dart:33`-`:54`），卡内排三行统计（`:38`-`:52`），点习惯行**不导航**（该文件的 `Navigator` 只出现在新建弹窗的 `pop`，`:95`、`:106`）⇒ 无月度表 |
| 补记打卡 | `:94` | 「**移动端 / 桌面端**：在「月度打卡表」中点击任意日期，即可补记打卡」 | `checkIn(int habitId, {DateTime? date})` 已支持按日期（`habit_repository.dart:72`），但全仓唯一调用方 `habit_page.dart:195` 从不传 `date` ⇒ 有通道、没入口 |

**契约现状（本 spec 首稿写错过，已改）**：`AppTodoHabitStatsRespVO.DailyCountVO` 确实有 `date` + `count`，
但后端 `yudao-module-todo/…/service/efficiency/habit/TodoHabitServiceImpl.java:140`-`:145` 是**造出来的**：
`:140` `for (int i = 6; i >= 0; i--) {`、`:142` `d.setDate(today.minusDays(i).toString());`、
`:143` `d.setCount(i % 2 == 0 ? 1 : 0);`（首稿写成 `:143`-`:145` 的「一行合并式」，那是**摘录**不是逐字锚点 ⇒ 改逐行）。
⇒ 每日次数与真实打卡无关，且**固定只回最近 7 天**（`period=MONTH` 只影响 `total`，`:129`）。
所以「补记」（FR-003）不需要改契约：`checkIn` 的 `date:` 已是真通道；
但「月度打卡表显示真实次数」（FR-002）**被服务端挡住**，已开 `zh-cloud-service` Issue #281。
客户端只做「渲染 API 给的 `dailyCounts`」这一件事：格子上有记录就显示次数、没有就显示未打卡，
**不在客户端补任何假数据**。
日期串的对齐靠用例自证：假仓库喂的是 `DateTime.toIso8601String()` 前 10 位（= Java `LocalDate.toString()` 的形状），
再断言这条记录的次数确实落在了那一天的格子上 ⇒ 客户端的 key 派生若与后端不同形就会红。

## 用户故事
我周一忘了打卡，周二想补上：点进这个习惯，看到当月的格子，点周一那一格就补记了。

## 功能需求
- **FR-001** 从习惯进入**当月**打卡表。源页 `:77` 是「点击习惯进入打卡页面，向上滑动即可查看当月打卡情况」⇒ 落地为：列表行点击仍进详情页（develop 既有 `InkWell`→`HabitDetailPage`），月度表挂在详情页「...」菜单里，菜单项文案取源页词「月度打卡表」（`:72`/`:94` 原文用词）。
- **FR-002** 打卡表把当月每一天都排成格子：后端 `dailyCounts` 里有记录的日期显示它的次数，没记录的显示「未打卡」。
  「整月逐日排格」是本端的**实现选择**，源页只给了「月度打卡表」这个名字与「点击任意日期」这个动作（`:94`），
  没有一句说空格子必须可见 ⇒ 不拿 `:72` 当依据（首稿把「即使哪一天没有背够5页的单词，也能记录自己完成3页的付出和努力」
  读成「看得见缺的日子」，那是**记付出**不是**看空格**，属过度归因，已作废）。
- **FR-003** 点任意一格即补记该日（源页 `:94`），调用 `checkIn(habitId, date: 该日)`，成功后刷新当月数据。
- **FR-004** 补记失败时：已经渲染出来的格子**不丢**，并在表内给出可见的错误文案（objective 四件套之「失败保留已加载数据」）。
- **FR-005** 每一格对读屏是可够到的按钮，announce 出「几号 + 当日次数」。
- **FR-006** 320px 宽 + 1.3 倍字号下当月格子**全部**渲染得出来（按当月真实天数精确断言，不是「至少 28」），
  且 1.3 倍这条要落在**弹层自己的 context** 上（单独一条用例读 `MediaQuery.textScalerOf(弹层节点)`，
  因为档位包在 `home:` 里传不进 `showModalBottomSheet` 的路由）。
- **FR-007** 连点两格会先后发两次刷新：先发后到的旧回包必须被丢弃，不得覆盖新数据。

## 取舍与被否方案
- **合并到 develop 时收回了「点列表行直接出表」这一处偏离**（原记于本文件与 PR !305 评论）：develop 已把列表行点击定为进详情页（`!291`/`a815c9a`），二者抢同一个手势；按 `:77` 原文取「点击进详情」为准，月度表下移到详情页「...」。被否的另一解是保留行点击弹表、把详情页另做入口 —— 否它是因为那会改掉 `!291` 已验收的列表行行为，且与源页句子相反。
- **落点用弹层（`showModalBottomSheet`）而不是新路由/新页面**：`:77` 说「进入打卡页面，向上滑动」、`:84` 说「右侧查看」，
  两种都要动信息架构（新增路由或改桌面右侧面板）；本端习惯分区目前只有一个列表页。
  按 objective「优先不改可见布局、入口放进已有表面」的决策规则，先落弹层，`仍缺` 里明写这一档与源页不完全一致。
  被否：新增 `HabitDetailPage` 路由（会把侧栏/dock 之外的第二套导航结构引进来，且 9 张黄金图里有 1 张能拍到 push 路由，改导航要重新评估基线）。
- **不做月份切换器**：源页只说「当月」，没给翻月交互 ⇒ 加了就是自创。
  但「没有翻月」≠「没有竞态」：首稿据此把「过期响应不覆盖新响应」判成不适用，是错的 ⇒
  每补记一次就发一次 `stats`，连点两格即两次在飞，先发的可能后到。已按 FR-007 加序号守卫与用例。
- **不禁止点未来日期**：源页 `:94` 只说「点击任意日期」，没写"过去的"；加日期上下限都是发明。
- **不做打卡样式（对勾/图标）与心情日志**：`:96`-`:97` 与 `:55` 是别的面，且心情/日志缺列（`habit_repository.dart:5`-`:6` 注明 schema 未含 `habit_logs`）。
