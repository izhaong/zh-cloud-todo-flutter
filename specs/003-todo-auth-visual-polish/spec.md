# Feature Specification: Todo 登录界面视觉与易用性优化

**Feature Branch**: `feat/87-todo-auth-visual-polish`
**Created**: 2026-07-12  
**Status**: Approved  
**Input**: 用户要求“Todo 的登录界面也优化一下”，并批准在不改变后端认证接口的前提下，同时优化视觉布局、用户文案、密码可见切换、加载/错误状态与响应式适配；用户授权 Agent 自主选择方案并直接交付结果。

## 1. 目标与范围

登录页是跨平台 Todo 客户端的入口，唯一任务是让用户快速、安全地进入自己的任务空间。本次改造沿用 002 的浅色品牌蓝、暖白画布、克制圆角与紧凑信息密度，不创建第二套视觉语言。

### In Scope

- 宽屏采用自适应双栏：左侧呈现 Todo 产品价值与任务节奏，右侧承载登录表单。
- 窄屏与移动端折叠为单栏，表单优先，保留品牌识别但减少装饰高度。
- 密码、短信验证码、注册和找回密码四种现有模式保持可达。
- 去除 `todo-member`、`token`、`用户池` 等面向实现的文案。
- 增加密码显示/隐藏、合理的自动填充提示、键盘动作与可见焦点。
- 统一加载、成功和错误反馈；繁忙时避免重复提交。
- 覆盖浅色/深色主题、常见宽度、文本缩放与基本语义测试。

### Out of Scope

- 不修改认证 API、请求字段、Session 持久化或路由行为。
- 不增加第三方登录、二维码登录、隐私协议流程或新的注册字段。
- 不重构认证数据层或引入新状态管理依赖。

## 2. 视觉方向

### 2.1 方案比较

1. **自适应任务工作台（采用）**：桌面双栏、移动单栏；产品识别最强，并能自然复用 002 的任务语义。
2. **增强型居中卡片**：改动最小，但桌面端仍显空旷，缺乏产品记忆点。
3. **沉浸式插画入口**：视觉冲击更强，但资产与维护成本高，也偏离当前克制的生产力工具气质。

### 2.2 设计令牌

- **Canvas**：复用 `AppColors.background`，不新增独立页面底色。
- **Surface**：复用 `AppColors.surface`；表单卡片仅使用细边框和低强度阴影。
- **Ink / Muted**：复用 `foreground`、`mutedForeground`。
- **Accent**：复用品牌蓝 `#2B7EFD`，只用于主操作、当前模式和必要焦点。
- **Success / Error**：复用现有语义色，不用纯装饰色表达状态。
- **Typography**：使用现有 Flutter 主题字体与字阶，标题强调但不引入额外字体依赖。

### 2.3 标志性元素

左栏使用一条“今日节奏”任务轨道：三个简短、真实的任务状态（已完成、进行中、稍后）组织成纵向节奏，而非通用插画或统计卡片。它只在宽屏完整展示；窄屏缩为品牌标题与一句价值说明。

## 3. 布局与组件

### 宽屏（>= 900px）

```text
┌──────────────────────────────────────────────────────────────┐
│  品牌 / 今日节奏（安静背景区）   │  登录模式 + 表单卡片        │
│  把今天安排得更清楚              │  欢迎回来                    │
│  ✓ 捕捉想法                      │  [密码] [验证码]             │
│  ● 完成本周计划                  │  手机号 / 密码 / 主操作       │
│  ○ 晚间回顾                      │  注册              忘记密码  │
└──────────────────────────────────────────────────────────────┘
```

- 页面内容设最大宽度，左右区域保持稳定比例；表单内容宽度不超过 420px。
- 左栏不放按钮，避免与登录主操作竞争。
- 表单标题与模式切换归入同一视觉容器，减少当前“切换器漂浮在卡片外”的割裂感。

### 窄屏（< 900px）

```text
┌──────────────────────────┐
│  Todo 标识 + 一句话价值   │
│  欢迎回来                 │
│  [密码] [验证码]          │
│  手机号 / 密码            │
│  登录                     │
│  注册          忘记密码   │
└──────────────────────────┘
```

- 使用安全区和可滚动容器；键盘弹出后主操作仍可到达。
- 320px 宽度不得横向溢出；按钮与输入控件触控高度不少于 48px。

## 4. 交互与文案

- 默认密码模式标题为“欢迎回来”，说明为“登录后继续安排任务与日程”。
- 验证码模式说明为“输入手机号，我们会发送登录验证码”。
- 注册说明为“验证手机号后即可开始使用”。
- 找回密码说明为“验证手机号并设置新密码”。
- 密码输入框提供显示/隐藏切换，默认隐藏，并提供明确语义标签。
- 手机号使用 telephone autofill；密码登录使用 password autofill；新密码使用 newPassword autofill；验证码使用 oneTimeCode autofill。
- 发送验证码沿用现有接口；发送中显示局部进度且禁用重复发送。
- 错误反馈放在表单字段与主操作之间，使用图标、语义色和可读文案；不得直接向用户展示异常对象或内部实现名称。
- 模式切换时清理无关敏感字段和旧反馈，保留手机号以减少重复输入。

## 5. 验收场景

1. 未登录用户在 1440px 桌面视口看到双栏布局，表单宽度稳定且主操作清晰。
2. 未登录用户在 390px 与 320px 视口看到单栏布局，无横向溢出且所有模式可达。
3. 用户点击密码可见按钮后能查看/再次隐藏密码，按钮语义随状态变化。
4. 用户切换密码、验证码、注册和找回密码时，标题、说明、字段与主操作正确变化。
5. 验证失败、验证码发送失败或登录失败时，页面显示面向用户的可操作错误，不暴露异常对象。
6. 提交或发送验证码期间，相关操作进入加载态且不能重复触发。
7. 主题切换、文本缩放到 200% 以及键盘导航时，内容仍可读、可聚焦、可操作。

## 6. 测试策略

- Widget 测试：默认内容、四模式切换、密码显隐、繁忙态、反馈语义。
- 响应式测试：1440、900、390、320 四档无溢出。
- 主题与可访问性测试：浅色/深色、200% 文本缩放、语义标签。
- 认证网关继续使用 Fake；测试不得访问真实后端。
- 完成后运行 `dart format --output=none --set-exit-if-changed lib test`、`flutter analyze` 与 `flutter test`。

## 7. 非功能约束

- 只复用 Flutter、Material 3 和仓库现有设计令牌，不增加依赖或外部图片资产。
- 保留现有测试依赖的关键 ValueKey；新增交互必须提供稳定 Key 或语义标签。
- 改动集中在认证表现层及对应测试，避免无关重构。
