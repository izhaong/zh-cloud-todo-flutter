## 二、本端现状与缺口（基准 zh-cloud-todo-flutter `origin/develop@9032005`）

| 面 | 判据 | 结论 |
| --- | --- | --- |
| 档位与入口（`:14`） | `lib/features/task/views/calendar_view.dart:212` `enum CalendarMode { month, week, year, list, agenda }`、`:226` label 为「日程」、`:376` `SegmentedButton<CalendarMode>` | **有**。本端 label 写作「日程」，原文写作「日程视图」——只记一处措辞差异，不算能力缺口 |
| 「一个时间轴…线性的方式」（`:5`） | 旧 `_AgendaView` 的过滤是 `date.year == anchor.year && date.month == anchor.month && date.day == anchor.day`（旧文件 `:887`-`:890`） | **缺**：只画锚点那一天 |
| 「同时看到过去已完成…和未来的计划」（`:7`） | 同上；单日过滤把过去与未来都排除在同屏之外 | **缺** |
| 数据面是否也缺 | `lib/features/home/home_shell.dart:777` 喂的是 `repo.watchAll()` 全量流，`:772`-`:775` 那个 window 只约束外部日历订阅事件 | **不缺** ⇒ 本单纯客户端，不动 service 契约 |

旧文件头注释 `:21`「日程模式：单日任务按时间顺序展示」把"单日"写成了设计意图。
以 `:5`「所有安排好时间的任务」为准，本单改正这条注释，注释与实现一起改，不留旧说法。

## 三、决定

1. 日程档画成**按日期升序的分组时间轴**：每个有落点日期的日子一个日头，日内沿用原有的 `_compareByTime`。
2. **不设窗口上下界**。原文只说「所有安排好时间的任务」，没给"最近 N 天"，于是本端也不引入这种截断（这类数字一旦写死就成了本端自创主张）。
3. 锚点语义保留：月视图点日期格仍走原来的「切 anchor 再切 agenda」（`calendar_view.dart:97`-`:99`），进入后那一天必须落在视口里。实现方式是统一行高 `88`，于是锚点偏移可算作 `锚点行号 × 88`，用 `ScrollController(initialScrollOffset:)` 直接给到初帧，不依赖"等布局完成再校正"。
4. 日头带 `Semantics(header: true)`，当天在日头后追加「今天」二字 —— 这是为了让人（和读屏）在一条长轴里认得出「当前的进度」落在哪一段（`:7`），不是新增档位。
5. 空态文案跟着改：旧文案「切换日期，或为任务设置开始和截止时间。」在跨日轴上不再成立（切换日期不会让轴变空）。

## 四、不主张的东西

- 「滚动鼠标滚轮即可轻松查看」(`:5`)：`ListView` 在桌面端天然吃滚轮，本单不另造滚动控件。
- 「过去已完成的任务」(`:7`) 的可见性由同页既有的「显示已完成」开关提供（`calendar_view.dart:318`，key `calendar-show-completed`），本单不加第二个开关。
- 源页 `:9` 与 `:16` 只有两张截图，没有额外文字主张 ⇒ 本面对 `05-日程视图` 这一页的判定到此为止。
