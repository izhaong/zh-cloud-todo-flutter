# 105 · 新任务默认值补「默认提醒」档（矩阵 #9 面 ⑥，FL 无单号）

## 背景

嘀嗒《02-功能指南/01-任务/04-超强大的提醒功能.md》`:31-:39`：

> 你可以通过修改「任务默认值」，在「设置」-「更多设置」-「任务默认值」-「默认提醒」中选择常用的提醒，将它设置为默认提醒。
> - 你还可以为任务设置「默认日期」、「默认优先级」、「默认清单」等等。

本端 `specs/055` 之前的「新任务默认值」页（`lib/features/settings/settings_route.dart` 的
`_TaskCaptureDefaultsPage`）只有「默认清单」「默认优先级」两档，**没有「默认提醒」**：
矩阵 #9 面 ⑥ 的判据 `git grep -n "默认提醒" origin/develop -- lib` 为 0 命中
（正向对照：同页「新任务默认值」3 命中），是 #9 保持「部分」的两个缺面之一。

面 ⑤「自定义提醒＝自由选择提醒时间点」经现读已可达：编辑提醒弹窗的
「指定时间（ABSOLUTE）」档就是日期 + 时间自由选择（`_pickReminderDateTime`），
矩阵里"本端是提前分钟数偏移"的旧断言只对锚点档成立，不覆盖 ABSOLUTE 档。

## 目标（FR）

- FR-1 「新任务默认值」页新增第三档「默认提醒」，选项照嘀嗒的常用提醒形态：
  **不提醒（默认）/ 准时 / 提前 5 分钟 / 提前 15 分钟 / 提前 30 分钟 / 提前 1 小时 / 提前 2 小时**。
- FR-2 保存走既有 `TaskCaptureDefaultsRepository`（`TASK_CAPTURE/defaults` 的
  view_preference 实体），跨端同步语义与既有两档一致；`defaultReminderMinutes`
  为 null 表示「不提醒」，保存 null 与保存 0 是两回事（null 不建提醒，0 = 准时提醒）。
- FR-3 消费点一（单条快速添加，`TaskQuickAddSheet._save`）：识别到 `dueAt` 建
  提醒时，`fireAt = dueAt - defaultReminderMinutes`；默认提醒为「不提醒」时行为不变
  （仍按 #388 的「识别到时间就建提醒」）；`fireAt` 落在过去时刻（<= now）时不建提醒、
  不报错——给一个已过期时间建提醒只会立刻响一次，不是用户要的。
- FR-4 消费点二（多行批量，`quick_add_batch_reminders.dart`）：`attachResolvedReminders`
  同样应用默认提醒偏移，规则同 FR-3；返回的失败语义不变。
- FR-5 既有行为零回归：不设默认提醒（null）时，单条与批量的提醒 fireAt 仍是识别时刻本身；
  已有的失败路径（提醒仓储不可用、写失败不回滚任务）逐字保留。

## 非目标

- 不做「默认日期」档（嘀嗒原文一句带过，且与识别语义冲突）。
- 不动服务端 `/task-defaults`（那是任务级 B2 兼容 API，与本用户级默认值不同物）。
- 不改提醒编辑弹窗（面 ⑤ 已可达）。

## 验收（AC）

- AC-1 设置页能选「提前 30 分钟」并保存；重进页面回读选中值；保存失败给可见提示。
- AC-2 单条快速添加「明天9点交报告」+ 默认提前 30 分钟 ⇒ 提醒 remindAt = 明天8点30，
  任务 dueAt 仍是 9 点。
- AC-3 默认提醒＝不提醒 ⇒ 提醒 remindAt 仍是识别时刻（现状锁）。
- AC-4 批量「写周报 明天9点\n买牛奶\n交材料 明天9点」+ 默认提前 15 分钟 ⇒ 两行各落
  一条 remindAt = 明天8点45 的提醒。
- AC-5 识别时刻减去默认分钟数 <= now ⇒ 不建提醒，任务照建，无失败提示。
- AC-6 全量门禁：`flutter analyze` 0 issue；既有全量用例通过（TZ=Asia/Shanghai）；
  新增用例全绿且各自配反向探针。
