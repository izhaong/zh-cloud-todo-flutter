## 决定

1. **范围只到 `:65` 那一面**：在既有的「高级筛选」对话框里加「预览模式」开关，开起来实时看
   "这样筛出来是哪些任务"。`applyTaskFilter` 是纯函数且已在仓里（`tasks_by_list_page.dart:2023`），
   复用它 ⇒ 预览与真套用的口径**同源**，不出现两套筛选实现。
2. **不新建第二份筛选实现**：由页面把 resolver 注进 `FilterBar`
   （`List<TodoTask> Function(TaskFilter draft)? previewResolver`）。
   `filter_bar.dart` 反过来 import 页面会成环（页面已 import 它），所以走注入。
   页面侧闭包用的就是 `_openFilterPanel(raw)` 手里那份**未过滤**的原始列表
   （`tasks_by_list_page.dart:209`），与列表渲染同一个入口（`:177`），数字不会两样。
3. **预览不写、不套、不入 outbox**：只读算一遍。套用的唯一路径仍是
   `应用高级筛选` → `onChanged(...)`（`filter_bar.dart:166`）。
4. **草稿优先**：开关关掉后，用户已输入的关键词/日期/负责人保留（本面不新增界面，
   「失败保留已加载数据」在这里的等价物是"别把用户填的东西吞掉"）。
5. 生效中的其它筛选维度（日期档/已完成/优先级）作为底板参与预览：
   预览算的是"当前这套条件全量生效后会看到什么"，不是只算高级面板那几个条件区（条件项逐条点名见本文件「验收」节）。

## 需求

- R1 高级筛选对话框里有「预览模式」开关，默认为关；关时不显示预览区。
- R2 打开后显示命中结果预览：含命中任务标题；不命中的标题不出现。
- R3 在预览态下改条件，预览跟着变；但生效中的筛选值不变（承载它的那格文案仍是原值）。
- R4 预览不产生任何持久化副作用：`todo_sync_changes` 行数不变，且不落库改任务。
- R5 关掉预览再打开，先前输入的草稿仍在。
- R6 读屏：开关与预览区各有独立语义（开关念得出「预览模式」，预览区念得出命中数）。
