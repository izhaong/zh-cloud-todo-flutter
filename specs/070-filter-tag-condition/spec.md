# 070 · 「筛选任务」对话框补「标签」筛选条件（FL Issue #420）

判据源：`zh-cloud-docs` 镜像《01-任务/09-如何管理海量任务/05-过滤器：随心所欲筛选你想看的任务.md》
（73 行，逐行引原文，术语照抄）：

- `:6`「在建立任务的时候，要尽可能的为任务添加「时间」、「标签」、「优先级」等属性，方便过滤器进行多维度筛选。」
- `:61`「高级筛选通过逻辑词：“或”、“且”以及清单、日期、优先级、标签等筛选条件可以进行多语句查询。」
- `:71`「你还可以使用“且”逻辑、“或”逻辑来关联前后两个筛选条件。并且，在同一个筛选条件（仅标签支持）内，也可以选择使用“且”逻辑、“或”逻辑。」

## 一、这一面在 FL 的位置

工作区顶部筛选条（`lib/features/filter/filter_bar.dart` 的 `FilterBar`）此前只有：全部 / 到期范围 / 完成情况 / 优先级 /
高级筛选（关键词、负责人、截止日期起止、预览模式）。`grep -c 标签 lib/features/filter/filter_bar.dart` 在开工前 = 0
⇒ 「按标签筛」在**这张面板上根本没有入口**（只有搜索页那张 sheet 有：`lib/features/task/task_search_filter_sheet.dart`）。
求值侧的标签分支已在 develop（FL PR !418，合并提交 `0c7bce9c4d74`），缺的只是把条件喂进去的那格。

## 二、本轮做与不做

做：在「高级筛选」对话框里加「标签」多选小节（`Text('标签')` + `Wrap(FilterChip)`，形态与术语照抄搜索页那一节），
选中结果写进 `TaskFilter.tagIds`，与「预览模式」同源实时算命中数，应用后筛选条入口的标签跟着显示。

不做（另立范围）：「且 / 或」逻辑词档位（`:71` 两句）= FL Issue #334；跨前后两个条件的布尔组合与多语句查询（`:61`）
要改 `TaskFilter` 的形状，也不在本单。本轮实现的选择仍按**缺省「且」**求值（与 `applyTaskFilter` 的
`containsAll` 同口径），不假装支持「或」。

## 三、口径

1. 多选即「且」：所选标签要全部命中才保留，缺省不给用户"或"的错觉。
2. 标签来源 `tagsStreamProvider`（`lib/state/providers.dart`），读不出（`hasError`）时小节显示「标签暂不可用，其余条件仍可继续筛选」，
   **不静默退化成"没有标签条件"**，也不清空对话框里已填的关键词。
3. 标签流后到一次不得重置草稿里已选中的标签（选择状态存在对话框自己的 `selectedTagIds`，不随流刷新）。
4. 预览与生效同源：预览走 `previewResolver`（页面注入的 `applyTaskFilter`），与列表同一把尺。
