# 041 笔记正文样式菜单（加粗 / 高亮）

## 来源（嘀嗒原文，不自行改写）
- 《03-特色功能/11-笔记与摘要.md:43》：「然后你就可以在笔记界面随心码字了。你可以使用键盘上方的样式菜单，给内容设置加粗、高亮等样式。」
- 标记形态取自《02-功能指南/01-任务/03-编辑与排版.md:48`-``:49》那张表：`**文字**` = 加粗、`==文字==` = 高亮。
- 矩阵落点：`zh-cloud-docs` 的 `dida-parity-matrix.md` 第 89 行 ②「添加笔记」小节里「样式菜单」这一面。

## 用户故事
作为记笔记的人，我在笔记正文里选中一段字，点「加粗」或「高亮」，就能看到成对 Markdown 标记把选中内容包住，
不需要自己敲星号。

## 功能需求
- FR-001 笔记编辑弹窗的内容框上方存在「加粗」与「高亮」两个动作（tooltip 同名）。
- FR-002 有选区时点击 ⇒ 选中片段被成对标记包住（加粗 `**`、高亮 `==`），且选区随之扩展到含标记，
  使「再点另一种样式」是叠加而不是把标记当正文再包一层。
- FR-003 光标折叠（没选中）时点击 ⇒ 插入成对标记并把光标落在中间，允许「先点样式后打字」。
- FR-004 样式只作用于内容框；标题框不受影响（嘀嗒那句只说「给内容设置样式」）。
- FR-005 320px 宽 + 1.3 倍系统字号下不溢出、无异常。

## 边界与不做什么
- 不做「取消样式」：嘀嗒《03-编辑与排版.md:60》说的是选中后可换/叠加样式，没要求反解标记。
- 不做工具栏以外的第三种样式（斜体、删除线等）—— 那一页本节只举了加粗与高亮两例，「等样式」不在本轮范围内落地。
- 不改笔记数据模型：标记就是正文文本，跟随 `content` 原样入库，渲染仍走 `flutter_markdown_plus`。

## 取舍与被否方案
- 采用「插入字面 Markdown 标记」而非真富文本 span：本端笔记正文已是 Markdown 纯文本
  （`note_page.dart:2` 引 `flutter_markdown_plus`、字段提示「内容（支持 Markdown）」），
  引入 span 级富文本等于重写渲染层，且与嘀嗒文档给出的语法不一致。
- 选区读取走 `TextEditingController.value.selection`（生产侧），而不是在测试里挖 `EditableTextState`：
  后者在 Flutter 3.44.8 没有公开 setter，测试只能用真键盘事件（Home / Shift + →）造选区，
  反而更贴近用户路径 —— 也顺带用上了嘀嗒《09-桌面快捷操作.md:68》要求的 Shift 精确选中。
- 向后选择（从右往左选）本轮按归一化后的 start/end 处理，不回写选区方向；影响仅是取消/继续选择时的锚点在左侧，
  留作后续（诚实记录，不谎称完整）。
