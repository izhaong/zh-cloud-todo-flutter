# Feature Specification: Todo 多端视觉高保真垂直切片

**Feature Branch**: `feat/85-todo-visual-fidelity`（Spec Kit feature ID: `002-todo-visual-fidelity`）

**Created**: 2026-07-11

**Status**: Complete

**Input**: 用户确认以唯一 C 端客户端为范围，同一应用覆盖网页、手机和 PC；先以 Web/PC `1440×900` 的今天/收集箱工作区为高保真基准，再映射到其它视口，不再以已删除的旧 Web Todo 为实现目标。

## Scope Decisions

- 本规格只处理视觉层级、布局密度、核心任务交互呈现、响应式映射和视觉回归验收。
- 第一验收基准是 Web/PC `1440×900` 的今天/收集箱工作区。
- 桌面基准通过后，同一任务流再适配紧凑桌面、平板和手机，而不是把桌面布局等比缩小。
- 本规格不改变账号、任务数据、同步规则、离线能力、后端接口或业务权限。
- 公开效率工具界面仅用于分析信息架构、布局比例、信息密度和交互规律；产品继续使用自有名称、图标、配色和文案，不复制第三方品牌素材。
- 已删除的旧 Web Todo 规格与计划只能作为历史经验，不能作为本规格的实现事实源。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 桌面用户获得清晰紧凑的任务工作区 (Priority: P1)

桌面或网页用户打开今天/收集箱后，可以立即识别全局模块、任务导航、任务列表和任务详情四个区域。主要空间用于扫描和处理任务，不被重复筛选器、卡片装饰或开发占位内容干扰。

**Why this priority**: 当前应用虽然已有三栏壳层，但任务列表仍呈现为控件堆叠和独立卡片，第一眼无法形成成熟任务管理产品的结构与密度；桌面主工作区是后续所有页面的视觉母版。

**Independent Test**: 在 `1440×900` 视口使用固定演示数据打开今天/收集箱，不连接真实服务，即可通过布局清单和截图对照独立验收四区结构、任务密度、选中态和视觉层级。

**Acceptance Scenarios**:

1. **Given** 用户在 `1440×900` 视口打开有任务的今天/收集箱，**When** 页面完成展示，**Then** 全局模块栏、任务导航栏、任务主区和任务详情区边界清晰，任务主区仍是视觉焦点。
2. **Given** 当前列表包含普通任务、置顶任务和多个日期分组，**When** 用户浏览列表，**Then** 未选中的任务以稳定的扁平列表行展示，分组标题、完成框、标题和时间可以快速扫描。
3. **Given** 用户选中一条任务，**When** 选中态出现，**Then** 仅该任务行获得克制的背景强调，未选中任务不呈现独立卡片边框或阴影。
4. **Given** 桌面主工作区已显示顶部快速添加栏，**When** 用户检查任务页，**Then** 不再同时出现第二套清单选择、智能清单按钮组、常驻视图按钮组或悬浮新建按钮来竞争主操作。

---

### User Story 2 - 用户在同一上下文完成快速添加与详情编辑 (Priority: P2)

用户无需离开当前任务列表即可快速添加、选择、查看和完成任务。选中任务后，右侧区域展示真实任务内容；未选中任务时，界面保持安静并给出最少必要引导，不展示伪造的详情占位内容。

**Why this priority**: 高保真不仅是颜色和尺寸，还取决于列表选择、详情联动和快速输入是否形成连续工作流。

**Independent Test**: 使用固定任务数据依次执行“输入任务并回车、选择任务、切换任务、完成任务、清空选择”，核对列表与详情状态始终一致，且不需要打开额外全屏页面。

**Acceptance Scenarios**:

1. **Given** 用户位于桌面任务主区，**When** 在快速添加栏输入标题并回车，**Then** 任务在一次输入动作后进入当前清单，输入栏清空且当前布局不跳转。
2. **Given** 用户点击任务行，**When** 任务成为当前选择，**Then** 右侧详情区展示该任务的标题、完成状态、日期、清单和正文等真实信息。
3. **Given** 用户从任务 A 切换到任务 B，**When** 点击任务 B，**Then** 列表选中态和右侧详情同时切换，不残留任务 A 的内容。
4. **Given** 当前没有选中任务，**When** 用户查看右侧区域，**Then** 仅展示 Todo 产品的中性选择引导，不展示开发说明或虚假字段。
5. **Given** 用户完成或取消完成任务，**When** 操作成功，**Then** 完成框、标题弱化和列表位置反馈保持一致，且主要内容不发生无关位移。

---

### User Story 3 - 用户在不同设备上获得适合该设备的同一任务流 (Priority: P3)

用户在紧凑桌面、平板和手机上仍能完成浏览、添加、选择、查看详情和完成任务，但导航和详情采用符合可用空间的呈现方式。

**Why this priority**: 该产品由同一客户端覆盖网页、手机和 PC；高保真不能只在单一宽度成立，也不能把桌面四区布局机械压缩到手机。

**Independent Test**: 使用相同固定数据分别在 `1280×800`、`1024×768`、`390×844` 和最小 `360×800` 视口完成核心任务流，确认没有溢出、遮挡或不可达操作。

**Acceptance Scenarios**:

1. **Given** 视口宽度不足以稳定容纳桌面四区，**When** 用户打开任务工作区，**Then** 次要导航或详情自动转为抽屉、覆盖层或独立页面，任务列表保持足够宽度。
2. **Given** 用户在手机上打开任务列表，**When** 添加或选择任务，**Then** 使用单列列表和移动端详情呈现，不出现被压缩的桌面侧栏。
3. **Given** 任务标题、清单名或标签较长，**When** 在任一验收视口展示，**Then** 主标题仍可识别，次要信息按既定规则截断、换行或收起，且操作控件不被挤出屏幕。
4. **Given** 用户切换浅色和深色主题，**When** 查看相同状态，**Then** 选择、日期、优先级和完成状态仍可区分，文字与背景保持可读。

### Edge Cases

- 当前清单为空时，仅显示轻量空状态和最短新建入口，不再叠加第二套新建按钮。
- 当前选中的任务被完成、删除、过滤掉或移动到其它清单时，详情区必须清空或切换到仍可见的有效任务，不能保留失效内容。
- 数据在同步后重新排序时，当前选择必须按任务身份保持，而不是按行号错误切换。
- 任务标题为超长中英文混排、Emoji 或无空格字符串时，任务行和详情标题不得水平溢出。
- 标签数量过多或日期、清单名同时存在时，任务主标题的可扫描性优先于展示全部元信息。
- 桌面窗口在四区、三栏、单栏临界宽度附近反复缩放时，不得出现布局抖动、重叠或连续开关抽屉。
- 深色主题不作为第一轮视觉复刻基准，但不得因浅色主题重构而失去可读性或状态区分。
- 演示数据和视觉验收不得连接真实后端、创建真实任务或暴露真实账号信息。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须以 Web/PC `1440×900` 作为第一视觉基准，展示全局模块、任务导航、任务主区和任务详情四个明确区域。
- **FR-002**: 系统必须让任务主区保持视觉焦点；外围导航和详情区只能使用中性背景、细分隔和克制的选中反馈。
- **FR-003**: 桌面任务页必须只保留一个主要快速添加入口，不得同时常驻第二套新建按钮或重复清单筛选控件。
- **FR-004**: 任务必须以稳定高度的扁平列表行展示；未选中行不得使用独立圆角卡片、常驻阴影或高对比边框。
- **FR-005**: 任务列表必须支持日期或业务分组标题，并在 `1440×900` 的标准有数据状态下一屏展示至少 10 条单行任务。
- **FR-006**: 任务行必须优先展示完成框和标题；日期、清单、标签、优先级及快捷操作属于次级信息，不能挤压主标题到不可识别。
- **FR-007**: 任务行的悬停、选中、完成、置顶、拖拽和键盘焦点状态必须彼此可区分，且只有当前相关状态显示快捷操作。
- **FR-008**: 快速添加必须允许用户输入标题并回车创建，创建后不离开当前列表，完整操作不超过一次聚焦加一次提交。
- **FR-009**: 桌面详情区必须绑定当前选中的真实任务；没有选中任务时只能展示中性空白或最少引导，不得展示开发占位文案。
- **FR-010**: 用户切换任务时，列表选中态与详情内容必须同步；当前任务失效时必须清理失效选择。
- **FR-011**: `1280×800`、`1024×768`、`390×844` 和 `360×800` 必须各有明确的导航与详情呈现规则，不得把桌面四区等比压缩。
- **FR-012**: 所有验收视口必须支持长标题、长清单名、多标签、空列表和无选中任务状态，且不得产生横向溢出或不可达操作。
- **FR-013**: 浅色主题必须作为第一轮高保真验收主题；深色主题必须保持文字、状态色和焦点的可读性。
- **FR-014**: 产品必须保持自有品牌表达，不得包含第三方 Logo、原始图标、插画、截图素材或营销文案。
- **FR-015**: 视觉验收必须使用确定性的非真实演示数据，覆盖有数据未选中、有数据已选中、空列表和长内容四类状态。
- **FR-016**: 每个批准的视觉状态必须形成可重复检查的基准；后续修改若超出约定容差，必须在评审中明确确认。
- **FR-017**: 本功能不得改变现有账号、任务数据、离线同步、服务端交互或业务权限行为。

### Key Entities

- **工作区状态**: 当前模块、当前智能清单或普通清单、当前任务选择、详情是否可见以及当前设备布局档位。
- **任务展示项**: 用于列表扫描的任务标题、完成状态、日期、清单、标签、优先级、置顶状态和选中状态。
- **任务分组**: 一组具有共同日期或业务属性的任务，以及分组标题、数量和展开状态。
- **视觉验收场景**: 由固定视口、主题、确定性演示数据、工作区状态和批准结果共同定义的可重复界面状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `1440×900` 桌面基准必须通过 `checklists/visual-acceptance.md` 的 10 项计分审计：总分至少 90/100，且四区结构、任务扁平化、单一快速添加、真实详情联动四项关键门槛必须全部通过。
- **SC-002**: `1440×900` 的标准有数据状态在任务主区一屏展示至少 10 条单行任务，且标题、完成框和时间均可辨识。
- **SC-003**: 用户完成“打开今天、添加任务、选择任务、完成任务”流程时，各步骤分别不超过一次目标点击或一次输入提交，不需要离开当前工作区。
- **SC-004**: 建立并批准 9 个视觉基准，覆盖 `1440×900`、`1280×800`、`1024×768`、`390×844` 与 `360×800` 中的有数据、已选中、空列表、长内容和移动详情状态。
- **SC-005**: 所有验收视口在长内容和大字号场景下均不存在横向溢出、文字覆盖主要操作或无法关闭的详情界面。
- **SC-006**: 现有任务创建、选择、编辑、完成、置顶和拖拽能力在视觉重构后仍可使用，自动化回归验证全部通过。
- **SC-007**: 视觉基准和交付物中第三方品牌素材数量为 0；所有图标、文案和空状态均来自本产品或通用系统资源。

## Assumptions

- 公开参考界面用于确定信息架构、比例、密度和交互规律，不作为需要逐像素复制的第三方图片资产。
- 第一轮以浅色桌面工作区为视觉母版，深色完整 polish 可在不阻塞主流程的后续切片继续收敛。
- 当前账号、数据、同步和任务领域能力可继续复用；本规格的主要差距集中在表现层。
- 演示数据中的日期、时间、数量和任务身份固定，确保不同机器和不同运行时间得到一致结果。
- 多端共享同一产品语言，但桌面使用多区工作台，手机使用单列导航和独立详情，不要求结构完全相同。
